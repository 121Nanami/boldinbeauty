## Lessons learned this run (read before resuming)
1. Left view without a reference: the reference upload needs ~5 s after attach. Sending the first view too early produced an unrelated cartoon girl. Fix: wait for the reference thumbnail, then reject any view card without a reference thumbnail.
2. Object wording: the view prompt must NOT say "character" / "A-pose" for props. Object-only wording (no people, no hands, no faces) fixed paper/ledger/card sets that came back as a person.
3. Signed image URLs expire in about an hour. Copies are in IndexedDB `bb2img` (key `<ID>|front|left|right|back`); the sets themselves persist in the account history.
4. Guard: before saving a set, each view is compared against its own front (mean colour of non-white pixels). Colour distance > 90 means wrong subject and the set is rejected.
5. Rate: single-view runs are safe. A burst of about 20 requests in a minute produced one HTTP 429 (stopped at once, resumed after a page refresh). Batches of 3 sets (about 12 images, front then views) ran without errors.
6. Style: human characters and NPCs get a gritty, mature, non-cartoon prefix (owner approved the look). Angel/operator designs were rated 10/10 by the owner; the angel sets regenerated in this run are new designs, the earlier ones are still in the account history.
7. Left and right views sometimes face the same direction; label by direction in the image if exact left/right matters. Never mirror.
8. Truly flat items (paper) are nearly invisible edge-on; PRP-0409 side views are almost empty.
